# OpenHypervisor

An open-source implementation of the `Hypervisor.framework` C API for arm64
macOS, built as `libopenhyp.dylib`. It is the Hypervisor library that
[iphone-cli](#compatibility)'s QEMU machine runs on.

- Exports the framework's C API, including private-surface symbols such as
  `_hv_vm_config_set_vhe_enabled` and `_hv_vcpu_get_context`, so a VMM
  written against `Hypervisor.framework` -- QEMU's HVF backend, for example
  -- relinks against it unchanged
- Links no Apple framework: every call goes to the kernel's hv trap through
  the library's own `svc` gate
- Adds what the framework does not offer: a C++ API, run-time switches and
  traces, and VMM extensions for timers, IPIs and the vCPU context layout

Use it in place of `-framework Hypervisor`: link with `-lopenhyp`, or keep
the SDK headers and swap only the library.

## Compatibility

| Host | Device | Guest builds verified |
| :-- | :-- | :-- |
| iphone-cli (QEMU `apple-iphone`, d16) | iPhone14,4 | iOS 15.0.1 (19A348), 16.0 (20A362), 17.0 (21A329), 18.6.2 (22G100), 26.0 (23A341) |

iphone-cli builds QEMU against this library (`-accel ohv`) to boot Apple's
own iPhone firmware as a nested EL2 guest.

| macOS host | hv interface | Status |
| :-- | :-- | :-- |
| 26.6.2 | 3.0.0 | in use on the iphone-cli regression hosts |
| 26A5388g (seed) | 3.0.4 | `tools/offset_probe`: every config field and the register block match, 14 of 18 trap ids directly; no drift |
| any kernel reporting 3.0.0, 3.0.2, 3.0.3 or 3.0.4 | | covered by the vCPU context layout table |
| any other hv interface version | | refused (`HV_UNSUPPORTED`), never guessed at |

The host must be an Apple-silicon Mac that is not itself a virtual machine
(`sysctl kern.hv_support` = 1). Inside a VM everything builds and the probes
run, but `hv_vm_create` returns `HV_UNSUPPORTED` (0xfae9400f).

A binary using this library needs the same entitlement as one using
`Hypervisor.framework`: the check is made by the kernel, which asks AMFI
whether the process holds `com.apple.security.hypervisor`. The test binaries
are signed with `tests/hv.ent`, which also carries the private
`com.apple.private.hypervisor` and is only accepted where AMFI is relaxed;
on a stock host build them with `HV_ENT=tests/hv-public.ent`. See
[Internals](docs/internals.md#entitlements).

## Build

The build runs on an arm64 Mac with the Xcode Command Line Tools (`clang`,
`clang++`, `make`, `codesign`). Nothing outside this repository is needed;
Python 3 is needed only to regenerate the generated sources.

```sh
make                       # libopenhyp.dylib + tests/smoke_bin + tests/smoke_static
make tests                 # every probe under tests/
make check                 # build the tests, then run each once
make offset_probe          # tools/offset_probe, the runtime offset matcher
make install PREFIX=/opt/openhyp   # lib/libopenhyp.dylib + include/openhyp/*
make uninstall PREFIX=/opt/openhyp
make clean
```

`make HV_ENT=tests/hv-public.ent tests` signs the test binaries with the
public entitlement only. `DESTDIR` is honoured by `install`. On a new macOS
build, run `make offset_probe && ./tools/offset_probe` first.

## Outputs

| File | What it is |
| --- | --- |
| `libopenhyp.dylib` | The library. Install name `@rpath/libopenhyp.dylib`; its headers are `include/openhyp/*`. |
| `tests/smoke_bin`, `tests/smoke_static` | The smoke test, linked against the dylib and statically. |
| `tests/<probe>`, `tests/<probe>_ohv` | Probes against the kernel trap, Apple's framework and this library (`make tests`). |
| `tools/offset_probe` | Re-derives the pinned offsets from the installed `Hypervisor.framework` and reports drift. |
